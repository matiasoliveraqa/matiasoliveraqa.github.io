Race condition in checkout causes double payment settlement without order creation

CRITICAL / P1
Environment: Staging v4.12 (Chromium 124, WebKit 17)
Discovery: Concurrency Fixture + Network Throttling

STEPS TO REPRODUCE:

1. Add item "Enterprise SKU-99" ($499.00) to checkout cart.
2. Input verified payment token and submit checkout form.
3. Simulate double-click or network packet delay (< 180ms delta) on payment authorization endpoint.
4. Inspect payment gateway balance and orders database table.

ACTUAL BEHAVIOR:

Two independent gateway charges processed ($998.00 total) while database transaction aborts on duplicate key error, leaving user charged with ZERO order generated.

EXPECTED BEHAVIOR:

Gateway idempotency key prevents duplicate charge and returns original transaction record (HTTP 200 with X-Idempotency-Replay header).

Isolated database seeding and AI-assisted synthetic mock generation ensure tests never conflict with shared staging data.
